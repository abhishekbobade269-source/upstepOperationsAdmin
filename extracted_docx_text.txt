DEMO SLOTS AUTOMATIONPlain-language explanation of the attached Google Apps ScriptPurposeCreates and keeps a Daily Slots sheet updated for demo scheduling.Code reviewedPasted code(1).js — 1,236 lines of Google Apps Script.Important noteThis review explains what the code is designed to do. It does not confirm that every linked spreadsheet, trigger, or HTML dialog is currently working.In one sentenceThe script works like a scheduling assistant: it reads coach availability and demo-related information from other Google Sheets, creates date-wise slot blocks in “Daily Slots”, and regularly updates the colours, remarks, preferences, and newly added demo slots.How the information flows• 1. Source schedule: It reads the Weekdays or Weekend tab from a separate scheduling spreadsheet, depending on the date being processed.• 2. Coach reference checks: It also reads a coach master sheet to identify coaches who should not receive demos, and a Demo Preference sheet to obtain each coach’s demo preference.• 3. Daily Slots output: It writes the selected slots into the active spreadsheet’s “Daily Slots” sheet in a six-column block for each date.• 4. Automation: A daily trigger can add the next date, while an hourly trigger refreshes existing future dates in smaller batches.What a date block containsColumnMeaning in simple languageCoach NameThe coach whose schedule is being shown.Start TimeThe time taken from the source schedule.1st 20 Mins / 2nd 20 MinsBlank working fields in this code; the script does not automatically fill them.RemarksFor example: X Demo, X Temporary, Missing in Schedule, or a schedule value.Demo PreferenceThe coach’s preference taken from the separate Demo Preference sheet.Core business rulesA slot is treated as an “X slot” and is included when either of the following is true:• The source day cell begins with “X” (such as X Demo, X Coverup, or X Temporary Class).• The same source cell has the purple background colour #9900ff, even if its text does not start with X.The script then sorts these slots by start time before adding them to a newly created date block.Colour and remark rulesConditionWhat the script doesBusiness meaningX Demo or X CoverupSets remark to “X Demo”.Treats these as demo-related slots.X Temporary ClassSets remark to “X Temporary”.Marks a temporary class case.A listed X slot changes to normal in sourceUsually changes its output background to red and copies the source text to Remarks.Flags that the earlier X/demonstration status is no longer active.Slot is no longer found in sourceSets remark to “Missing in Schedule” and colours the row light red.Warns that the slot may have been removed from the schedule.Coach has no demo eligibilityChanges only the Coach Name cell to pink (#EA9999).Visual alert: both Foundation Demo and Master Demo are blank, No, Hold, or On Hold.Demo preference existsWrites the preference and applies its mapped colour in the last column.Makes preference visible: preference 1 green, preference 2 light green, preference 3 yellow, not-to-be-given/to-be-updated red.How new slots are created• Manual creation: An allowed user selects “Create Sorted X Slots”, enters the number of future days, confirms a warning, and the script creates missing dates.• Daily creation: A scheduled job can run daily at approximately 1 AM in the script’s time zone. It finds the latest date already present and adds the next date. It can be paused using an internal ON/OFF setting without deleting the trigger.• Layout: For every new date, the script inserts seven columns at the left side: six working columns plus one spacer. The first row shows the date and weekday; the second row has the six headings.• Protection: During the update it removes the sheet filter, adds a temporary warning-only sheet protection, then removes that temporary protection when finished.How the hourly update worksThe update does not rebuild everything from scratch. For each future date already visible in Daily Slots, it compares the existing coach + start-time combination with the current source schedule. It then updates colours, remarks, preferences, and missing entries; it also appends X slots that are new in the source schedule.To avoid Google Apps Script time limits, each run processes a maximum of three date blocks or about 4.5 minutes of work. If more dates remain, it stores its position and creates a one-time continuation job for roughly 30 seconds later. The next hourly run starts again from the beginning.Who can use itRoleAccess provided by the codeSpreadsheet ownerAlways treated as an administrator.Additional administratorCan manage admin users, allowed users, locks, and install triggers, plus perform the normal slot actions.Allowed userCan update all slots, create future X slots, and select the “Mark Absent Dates” menu item.Other userSees an access-denied option, or “Identify Me” if Google cannot determine their email address.Admins and allowed users are saved in the spreadsheet’s document properties. A user’s manually identified email is saved in that user’s own script properties.Important limitations and points to verify• Sort-by-colour risk. The code explicitly warns that it cannot detect “Sort by colour”. If users sort data that way, values may no longer match their intended rows. The script removes normal filters before it runs.• Absent-date feature is not built. The menu displays “Mark Absent Dates”, but the function only shows “Not implemented here.” It does not perform an absence action.• Some screens are outside this file. AdminDialog and AccessDialog HTML files are required for the management windows. They were not included with the JavaScript, so their behaviour cannot be reviewed here.• Spreadsheet access is essential. The account running the automation must have access to all three linked spreadsheets. The code retries access three times and then shows a permission/not-found error.• Colour is part of the business data. Several decisions depend on exact hex colours—especially purple #9900ff and red #ff0000. Manual colour changes can therefore change the script’s outcome.• Name matching must be clean. Coach names are matched mainly using trimmed, lower-case text. Differences such as alternate spellings, duplicate names, or inconsistent spacing can cause a preference or no-demo flag not to match.• Trigger timing is approximate. Google’s time-based triggers run near the chosen hour, not necessarily at an exact minute. Confirm the Apps Script project time zone is the one operations expects.• Sheet lock is not a full edit lock during runs. The temporary protection is warning-only, so it warns users rather than strictly preventing edits. The separate Admin Lock is a real lock for non-admins.Recommended operating practice• Keep source headers unchanged: The script looks for exact headings such as “SF Coach Name”, “Start T”, coach/demo preference fields, and weekday names.• Use one standard naming convention: Maintain the same coach name across schedule, coach master, and preference sheets.• Do not manually use script-control colours casually: Treat purple and red as operational status colours, not decorative formatting.• Test after any layout change: Before changing a source sheet structure, test in a copy because the script refers to fixed sheet names, column headers, date rows, and row positions.• Review the inactive/unfinished features: Either implement “Mark Absent Dates” or remove it from the menu to avoid user confusion.• Restrict admin rights: Admins can install triggers, change access lists, lock/unlock the sheet, and potentially affect all scheduled updates.Bottom lineThis is a practical Google Sheets-based slot-management automation. Its main job is to give operations a date-wise list of demo/X slots, maintain the visual status of those slots, and highlight coach eligibility and demo preferences. It is dependent on consistent source-sheet structure, accurate colours, permissions to linked files, and careful user behaviour around sorting and manual edits.
